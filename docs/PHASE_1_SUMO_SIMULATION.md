

# Phase 1: SUMO Traffic Simulation

## Overview

Phase 1 establishes the simulation foundation for the Smart Traffic Management Platform. Using **SUMO (Simulation of Urban MObility)**, we model the physical road networks and synthetic traffic flows of the Kaduwela-Colombo corridor in Sri Lanka. This simulation serves as our data-generation engine, producing realistic traffic datasets used to train machine learning models and validate agent-based signal control algorithms.

---

## Simulated Network Geometry

The simulation covers five key junctions along the Sri Lankan highway network:
1. **Kaduwela Junction:** The primary 4-way intersection connecting through-traffic.
2. **Malabe Junction:** A busy 3-way T-junction connecting Kaduwela, Athurugiriya, and Battaramulla.
3. **Biyagama Junction:** Connecting the industrial zone traffic to the main corridor.
4. **Kotikawatta Junction:** Managing urban incoming queues.
5. **Ranala Junction:** Handling transit and local traffic inputs.

### Network Files structure (`simulation/`)

For each junction, the network is defined by a set of XML configurations compiled into a unified SUMO net file:
* **Node files (`*.nod.xml`):** Define the coordinate junctions (intersections and endpoints).
* **Edge files (`*.edg.xml`):** Define the roads, their lane counts, speed limits, and directions.
* **Connection files (`*.con.xml`):** Specify lane-to-lane turning logic at junctions.
* **Network files (`*.net.xml`):** Compiled binary networks generated via `netconvert`.
* **Route files (`*.rou.xml`):** Define vehicle paths and flow distributions.
* **Configuration files (`*.sumocfg`):** Combine the network, route, and settings files for simulation.

## Traffic Demand Modeling

To ensure the simulation reflects real-world Sri Lankan traffic patterns, the flow definitions simulate three distinct periods across a 24-hour cycle:

1. **Peak Hours (06:00 - 09:00, 13:00 - 14:30, 17:00 - 19:00):** High vehicle generation rates, prioritizing main inbound directions in the morning and outbound directions in the evening.
2. **Off-Peak Hours (09:00 - 13:00, 14:30 - 17:00, 19:00 - 22:00):** Balanced, moderate traffic.
3. **Night Hours (22:00 - 06:00):** Low traffic densities, mainly consisting of heavy trucks and transit vehicles.

### Vehicle Types modeled

The simulation populates five vehicle categories with distinct lengths, acceleration profiles, and maximum speeds:
* **Cars:** Standard personal transit.
* **Buses:** High occupancy, slower acceleration.
* **Motorcycles:** Short length, high maneuverability.
* **Tuk-Tuks:** Three-wheelers with low speed caps (40 km/h).
* **Trucks:** Long freight vehicles.

## Weather Effects Simulation

A key feature of the simulation is its dynamic weather engine. Weather conditions directly scale the maximum speeds of vehicles on the road network to model real-world slowdowns under adverse conditions.

The speed multiplier mapping configured in `run_simulation.py`:

| Weather Condition | Speed Multiplier | Impact Description |
|-------------------|------------------|--------------------|
| **clear**         | 1.00             | Optimal conditions, standard speed limits. |
| **overcast**      | 0.95             | Minor visibility limits. |
| **light_rain**    | 0.85             | Wet roads, safety distance increase. |
| **foggy**         | 0.78             | Significantly reduced visibility and speed. |
| **heavy_rain**    | 0.65             | Maximum slowdown, potential water logging. |

## Python-TraCI Control & Data Extraction

The script [run_simulation.py](file:///c:/Users/hirun/Desktop/Smart-Traffic-Management-Platform%201/Smart-Traffic-Management-Platform/simulation/scripts/run_simulation.py) acts as a wrapper that launches SUMO, runs the simulation step-by-step, applies weather modifiers, and extracts traffic measurements.

### Data Extraction Process
At every **60 simulation steps (equal to 1 minute of real time)**, the script queries the state of incoming junction edges to extract:
* **Vehicle Count:** Total vehicles currently occupying the incoming road edge.
* **Wait Time:** Total cumulative wait time (speed < 0.1 m/s) of all vehicles on that edge.
* **Queue Length:** Number of stopped vehicles in the lane queues.

### Script Execution Commands

**To run a headless simulation (faster):**
```bash
python simulation/scripts/run_simulation.py --junction malabe --weather clear
```

**To run with the SUMO GUI (visual debugger):**
```bash
python simulation/scripts/run_simulation.py --junction kaduwela --weather light_rain --gui
```

## Generated Dataset Schema

The data generated by Phase 1 is stored in the `data/processed/` directory. It forms the basis of the ML model training dataset.

**Attributes extracted:**
* `date`: Day of the simulation run.
* `hour`: Hour of the day (0-23).
* `junction`: Name of the junction (e.g. `Kaduwela`).
* `<arm>_total`: Total vehicles present on the specific incoming arm.
* `<arm>_wait_sec`: Total wait time in seconds on that arm.
* `<arm>_queue`: Total queue count on that arm.
